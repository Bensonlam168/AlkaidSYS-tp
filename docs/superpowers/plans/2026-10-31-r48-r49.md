## 已核实的框架事实（省得你再踩）

1. `AbstractMigration::execute(string $sql, array $params = []): int` —— **支持参数绑定**
2. `AbstractMigration::query(string $sql, array $params = [])` —— **支持参数绑定**，但返回类型未证（需你实测确认是 `PDOStatement` 还是别的）
3. `fetchAll(string $sql)` / `fetchRow(string $sql)` —— **不支持**参数绑定，别用它们做带参查询
4. Seeder 里 `$this->output` 恒为 `null`（think-migration 的 `executeSeed()` 从不 `setOutput`）→ 必须用已有的 `writeLine()` 兜底，**不要**直接 `$this->output->writeln()`
5. `think\Console::run()` 只捕获 `\Exception` → **要保证 exit 非 0，必须抛 `\Exception` 子类**（`RuntimeException` 可以），抛 `\Error` 会「优雅报错但 exit 0」

## Review Focus

- **顺序无关**：把 `run()` 里的步骤顺序临时对调（先 assign 后 create），结果必须**仍然是 role2 = 3**（靠 assign 内部确保，而不是靠顺序正确）
- **缺 slug 响亮失败**：把某个 slug 改成错字 → `seed:run` 必须**抛异常并列出缺失的 slug**，不能静默 0 行
- **参数化真生效**：权限名里临时加一个半角单引号（如 `View O'Brien Forms`）→ 插入必须成功且数据正确（证明不再靠字符串拼接）
- **幂等不退化**：全新库 seed 双跑，所有表行数不变

### 1.1 R49：`createPermissions()` 改参数化
- 把 `sprintf` 拼接改为 `$this->execute($sql, $params)`
- 保留 `FROM DUAL` + `WHERE NOT EXISTS (... = ?)` 的幂等语义（`FROM DUAL` 不能去掉：MySQL 对无 FROM 的 SELECT 可能把 WHERE 优化掉）

- 加中文注释说明：**这些值来自代码内常量、本无注入面**，改参数化是为了消除「权限名含单引号会破 SQL」这类脆弱性（R49 是健壮性改进，不是安全漏洞修复）

### 1.2 R48：role 2 授权改为「确保 → 断言 → 按 id 插入」
`assignPermissionsToRoles()` 里 role 2 那段目前是 `... WHERE p.slug IN ('forms.view', 'form_data.view', 'collections.view')`，两个静默失败模式：
- 若 `createPermissions()` 尚未执行 → 匹配 0 行，无报错
- 若某个 slug 被改名/打错 → 匹配 0 行，无报错

改为：
1. **确保**：在方法开头调用权限确保逻辑（把 `createPermissions()` 抽出为可复用的私有方法，或直接调用它——它已幂等）。这样 `assignPermissionsToRoles()` **不再依赖 `run()` 的步骤顺序**
2. **断言**：用 `query($sql, $params)` 按 3 个 slug 查真实 id；查到的 slug 集合与期望集合比对，**缺任何一个就抛 `RuntimeException`**，消息里列出缺失的 slug 与期望清单
3. **按 id 插入**：用断言得到的 id 数组插入（参数化），保持 `NOT EXISTS` 幂等
4. 加中文注释说明这三步各自防的是什么

- [ ] 先实测 `query($sql, $params)` 的返回类型（写个一次性探针），确定怎么取行；若它不可用，**先报告**再决定替代方案（不要退回到字符串拼接）

**注意**：`run()` 里是否保留独立的 `createPermissions()` 步骤由你决定，但必须在注释里说明「assign 内部也会确保一次，重复调用是幂等 no-op」。
