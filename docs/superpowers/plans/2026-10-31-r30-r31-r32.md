## Task 2：R32 清伪键 + 写规则

**Files:**
- Modify: `.env.example`
- Modify: `AGENTS.md`

**已核实事实**
1. `.env.example` 里 4 行注释被 `parse_ini_file` 解析成了**伪键**（因注释行含 `=`）：
   - `:35  # 1. 生产类环境（APP_ENV = production / prod / stage / staging，或未设置 APP_ENV）：`
   - `:41  # 2. 非生产环境（APP_ENV = dev / local / testing）：`
   - `:47  #    注意：docker compose 已为后端容器设置 APP_ENV=dev；若在容器外直接运行，请自行设置 APP_ENV=dev。`
   - `:55  # 留空 = 关闭自助注册（注册接口返回 403 / code 2008）。`
   解析出的键形如 `# 1. 生产类环境（APP_ENV`，因带 `#` 前缀**不会**覆盖真实键，但属噪音，
   且掩盖了「注释里含 `=` 会变键」这一危险模式。
2. `AGENTS.md` 的 `## Configuration & Security`（约 `:110-113`）是写入规则的合适位置。

**要做**
### 2.1 清伪键（保持语义不变）
把上述 4 行里的 `=` 改成不产生键值对的写法，例如用全角「＝」、改写成「：」或调整语序。
**要求**：注释可读性不下降，且解析后不再出现 `#` 开头的键。

### 2.2 `AGENTS.md` 加规则
在 `## Configuration & Security` 里加一条，内容要点：
- `.env` / `.env.example` 的注释行**禁用 ASCII 括号与引号**（`( ) " ' [ ] { }` 等）——
  `parse_ini_file` 会报语法错误，导致**整份文件解析失败、所有键静默失效**
  （`Env::load()` 拿到 `false` → `?: []`），表现为「容器起来了但连不上库」这类极难定位的问题
- 需要括号时用**全角括号**（`（）`）
- 注释里也避免出现 `=` 形式，否则会被解析成伪键
- 说明自查方式（例如 `php -r 'var_dump(parse_ini_file(".env", true, INI_SCANNER_RAW) !== false);'`）

**验证**
- `parse_ini_file('/var/www/html/.env.example', true, INI_SCANNER_RAW)` 不返回 `false`
- 解析结果的键集合**只含合法大写键名**（无 `#` 开头的键）
- 5 个 DB 键取值仍正确（`mysql` / `alkaid_sys` / `root` / `root` / `utf8mb4`）
- `AGENTS.md` 改动后 `check-docs.php --strict` 仍 exit=0（AGENTS.md 是否在其扫描范围需确认；若不在，说明即可）
- 三处既有门禁 exit=0
