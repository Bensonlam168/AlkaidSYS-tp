# R33 / R34 / R35 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development

**Goal:** 给 `.env.example` 加 CI 门禁；让 phpunit 配置检查递归覆盖子目录；给豁免清单加到期复核机制。

**Architecture:** R33 是新增一个纯 PHP 脚本 + 一个 CI 工作流（照 `docs-check.yml`）；R34/R35 都改 `scripts/check-phpunit-config.php`（把根层 `glob` 换成递归扫描 + 排除目录；把 `EXEMPT_CONFIGS` 从字符串改成带 `review_by` 的结构）。

**Tech Stack:** PHP 8.2（无框架依赖）/ GitHub Actions

**Spec:** 上一轮修复清单的 R33 / R34 / R35

## Global Constraints

- 中文注释与提交信息；**不得推送**；提交用 `git -c core.hooksPath=/dev/null commit`
- 全量失败集去重必须 **≤ 41**（当前 41，用例 520）
- 四道既有门禁 exit=0：`check-migrations`、`check-docs`、`check-phpunit-config`、`lang:check`
- **worker 不得并行跑 phpunit**；本计划的验证都不需要跑 phpunit

## Review Focus

- **递归扫描不得把 vendor 卷进来**：`plugins/workflow-engine/vendor/` 下有 2 个 `phpunit*.xml`；同时 `plugins/workflow-engine/phpunit.xml` 是**真实**插件配置（有 env、无 force），必须被识别并登记或豁免，而不是靠"扫不到"侥幸跳过。
- **豁免到期必须真的挡住**：把某条豁免的 `review_by` 改成过去日期 → 门禁必须 exit=1 并点名要求复核。
- **`.env.example` 门禁要能抓住两类历史故障**：ASCII 括号导致整份解析失败、注释含 `=` 产生伪键。
- **新增的两条 CI 工作流不能互相打架**，也不要把触发路径写得永远不命中。

## Task 1：R34 递归扫描 + R35 豁免复核机制

**Files:**
- Modify: `scripts/check-phpunit-config.php`

**已核实事实**
1. 现状 `:210` 用 `glob(REPO_ROOT . '/phpunit*.xml')` —— **只扫根层**。
2. 仓库内 `phpunit*.xml` 实际分布：
   - 根层 4 个：`phpunit.xml`、`phpunit.t048.xml`、`phpunit.t050.xml`、`phpunit.performance.xml`
   - `plugins/workflow-engine/phpunit.xml`（**被 git 跟踪的真实配置**，含 10 个 `<env>`：`APP_ENV=testing`、
     `DB_CONNECTION`、`DB_HOST=127.0.0.1`、`DB_PORT`、`DB_DATABASE`、`DB_USERNAME`、`DB_PASSWORD`、
     `WORKFLOW_DB_PREFIX`、`WORKFLOW_TENANT_ENABLED`、`WORKFLOW_DEBUG`；**全部不带 force**）
   - `plugins/workflow-engine/vendor/topthink/think-swoole/phpunit.xml` 与另一处 vendor 文件（**必须排除**）
3. `EXEMPT_CONFIGS` 目前是 `basename => 理由字符串`，无到期概念。

**要做**
### 1.1 递归扫描（R34）
- 把根层 `glob` 换成递归（`RecursiveDirectoryIterator` 或 `glob('**', GLOB_BRACE)` 均可），
  **排除** `vendor/`、`node_modules/`、`.git/`、`runtime/`
- 检查 D 的「未登记」判定要按**相对路径**而非 basename，否则 `plugins/.../phpunit.xml` 与根层同名会混淆
- 工作流 `.github/workflows/phpunit-config-check.yml` 的 `paths` 改为能命中子目录（`'**/phpunit*.xml'`）
- 把 `plugins/workflow-engine/phpunit.xml` 登记为**豁免**（它属插件独立测试域，且全部 env 不带 force），
  理由里写明「插件独立测试域，env 无 force，不参与根级强制变量策略」

### 1.2 豁免复核机制（R35）
- `EXEMPT_CONFIGS` 改为结构化：
  ```php
  const EXEMPT_CONFIGS = [
      'phpunit.performance.xml' => [
          'reason'    => '...',
          'review_by' => '2027-04-30',   // 到期后门禁报错，要求重新复核
      ],
      'plugins/workflow-engine/phpunit.xml' => [
          'reason'    => '...',
          'review_by' => '2027-04-30',
      ],
  ];
  ```
- 新增**检查 E：豁免复核到期**
  - `review_by` 未设置或格式非法（非 `YYYY-MM-DD`）→ 错误
  - 当前日期 > `review_by` → 错误，提示「豁免已到期，请复核后更新 review_by 或移除豁免」
  - 未到期 → 每次运行**打印**该豁免及其剩余天数（可见性，避免"设了就不管"）
- 保留既有语义：豁免只对检查 A / C 生效；检查 B（`DB_*` 不得 force）对**所有**配置生效

**验证（必须给原始输出）**
- 正常态：`php scripts/check-phpunit-config.php --strict` → exit=0，检查 0/A/B/C/D/E 全 OK，
  且打印两条豁免的 `review_by` 与剩余天数
- **递归生效**：临时在 `tests/fixtures/phpunit.bogus.xml` 放一个未登记配置 → 检查 D 报 `[UNREGISTERED]` 且点名**相对路径**；删除后恢复
- **vendor 未被卷入**：确认输出里不出现任何 `vendor/` 路径
- **豁免到期拦截**：把某条 `review_by` 临时改成 `2020-01-01` → 检查 E 报错、exit=1；还原
- **豁免格式校验**：把 `review_by` 改成 `2027/04/30`（斜杠）→ 检查 E 报格式错误；还原
- 四道门禁 exit=0

## Task 2：R33 `.env.example` CI 门禁

**Files:**
- Create: `scripts/check-env-example.php`
- Create: `.github/workflows/env-check.yml`

**已核实事实**
1. `parse_ini_file($file, true, INI_SCANNER_RAW)` 对注释行里的 **ASCII 括号/引号**会报语法错误 → 返回 `false`
   → ThinkPHP `Env::load()` 拿到 `false` 后按 `?: []` 兜底 → **所有键静默失效**
2. 注释行含半角 `=` 会产生**伪键**（键名形如 `# 1. 生产类环境（APP_ENV`）
3. `AGENTS.md` 已写入这两条规则（R32），并给出两条自查命令 —— 但**没有 CI 拦截**（这就是 R33）
4. 当前 `.env.example`：13 个键、0 个伪键

**要做**
### 2.1 `scripts/check-env-example.php`
纯 PHP，无框架依赖，支持 `--strict`，退出码 0/1，输出风格与 `check-docs.php` 一致。

检查项：
- **检查 A：可解析** —— `parse_ini_file(...)` 不得返回 `false`；失败时把 PHP 的 syntax error 行号带出来
- **检查 B：无伪键** —— 所有键名必须匹配 `^[A-Z][A-Z0-9_]*$`
- **检查 C：注释里无 ASCII 括号/引号** —— 逐行检查注释行（`^#` 或 `^;`），
  命中 `( ) " ' [ ] { }` 即报错并给出**行号与原文**（这是 A 的成因，单独报更易定位）
- **检查 D：必需键存在** —— 至少要有 `DB_HOST`、`DB_NAME`、`DB_USER`、`DB_PASS`、`DB_CHARSET`、`JWT_SECRET`
  （若某天真的移除，需同步改本检查，属显式决策而非静默丢失）
- 可选：`.env` 若存在，做**只读**的键集合对比并给出提示（不报错，因为 `.env` 未跟踪、可能含本地增补）

### 2.2 `.github/workflows/env-check.yml`
照 `docs-check.yml` 结构；触发路径：`.env.example`、`scripts/check-env-example.php`、工作流自身、
以及 `AGENTS.md`（规则改了也可能影响）；一个 job 跑 `php scripts/check-env-example.php --strict`。

**验证（必须给原始输出）**
- 正常态 exit=0，检查 A/B/C/D 全 OK
- 三条破坏性验证（每条做完**立即还原**，还原后确认 exit=0）：
  1. 注释里注入 ASCII `(` `)` → 检查 A 与 C 都应报错、exit=1
  2. 注释里注入 `# 测试 = 值` → 检查 B 报伪键并给行号
  3. 删掉 `JWT_SECRET` 键 → 检查 D 报缺失
- 四道既有门禁 exit=0
- 工作流 YAML 可被解析（用 `ruby -ryaml -e 'YAML.load_file(...)'` 或等价方式）
