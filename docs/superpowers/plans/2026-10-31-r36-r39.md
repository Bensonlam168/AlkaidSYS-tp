## Task 1：R37 `.env` 解析失败不再静默 + `env:check` 覆盖

**Files:**
- Modify: `app/command/EnvCheckCommand.php`
- Modify: `app/AppService.php`
- Test: `tests/Unit/Command/EnvCheckCommandTest.php`（新建；若已存在同类测试则扩展）

**已核实事实**
1. `env:check` 命令**已存在**（`app/command/EnvCheckCommand.php`，347 行，已在 `config/console.php` 注册），
   做的是 DB/JWT/Redis/Casbin/RateLimit/CORS 各变量的取值校验 —— **它不检查 `.env` 能否被解析**。
2. `execute()` 的结构：`loadEnvDefinitions()` → 读 `--strict/--generate` → 逐变量 `checkVariable()` →
   `outputSummary()` → 有 error 返回 1。
3. `think\Env::load()` 的实现是 `parse_ini_file($file, true, INI_SCANNER_RAW) ?: []` ——
   **解析失败时拿到空数组**，所有键静默失效（vendor 代码，不可改）。
4. `app/AppService.php` 的 `boot()` 已有插件加载与 provider 接线逻辑，是会执行到的早期钩子。
5. `parse_ini_file` 对注释行里的 ASCII 括号/引号会报 `syntax error`（R32/R33 已确立）。

**要做**
### 1.1 `EnvCheckCommand` 加 `.env` 解析检查
- 在 `execute()` **最前面**（`loadEnvDefinitions()` 之前）插入一步：
  - 取 `.env` 路径（`$this->app->getRootPath() . '.env'`）
  - 文件不存在 → **跳过**（不是错误；容器可只用环境变量）
  - 文件存在 → `parse_ini_file($path, true, INI_SCANNER_RAW)`；用 `set_error_handler` 捕获 warning，
    拿到 `syntax error ... on line N` 的行号与出错行原文
  - 解析失败 → 输出 error（含行号 + 原文 + 后果说明），**直接把该错误计入 errors 汇总**，
    并**跳过后续变量检查**（否则会因为所有键为空而报一堆误导性的「缺失」错误）
- 输出格式与既有 `✗/⚠/✓` 风格一致

### 1.2 `AppService::boot()` 加运行期守卫
- 在 `boot()` **最前面**加：
  - `.env` 不存在 → 直接继续
  - `.env` 存在但解析失败 → 抛 `RuntimeException`，消息包含：错误行号、出错行原文、
    以及「请在 .env 注释里使用全角括号，见 AGENTS.md Configuration & Security」
- 用 `static` 变量缓存结果，避免每次请求重复 `parse_ini_file`（文件很小，但没必要重复）
- **不要**把异常吞掉（不要 try/catch 后只记日志）——这一条的目的就是响亮失败

### 1.3 测试
- 新建 `tests/Unit/Command/EnvCheckCommandTest.php`：
  - 正常 `.env` → exit 0
  - 临时把 `.env` 换成一个含 ASCII 括号的版本 → 命令 exit 1，输出含行号
    （**必须用完立即还原**，用 sha256 证明）
  - `.env` 不存在时：可临时改名验证「跳过而非报错」，或直接说明该项未测及原因

**验证（必须给原始输出）**
- `php think env:check` 正常态 exit=0
- 注入 ASCII 括号后：`php think env:check` exit=1 且输出含行号与原文；**还原**（sha256 一致）
- 注入后触发运行期守卫：在容器内跑一条最小请求/命令，确认抛 `RuntimeException` 且消息含行号；
  **还原**后确认恢复正常
- **全量测试 520 用例仍绿**，失败集去重 ≤ 41（与基线 diff）
- 五道门禁 exit=0
