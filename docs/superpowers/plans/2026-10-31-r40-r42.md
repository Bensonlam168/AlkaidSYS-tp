# R40 / R41 / R42 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development

**Goal:** 让三个配置类门禁能真正被设为 required check（去掉 `paths:`）；补 `check-migrations` 的工作流；把环境守卫的进程缓存做成「文件没变就零解析、文件变了能自愈」。

**Architecture:** R40/R41 都是 `.github/workflows/` 下的 YAML；R42 改 `app/AppService.php` 的缓存签名 + 补测试。

**Tech Stack:** GitHub Actions / ThinkPHP 8 / PHP 8.2

**Spec:** 上一轮修复清单的 R40 / R41 / R42

## Global Constraints

- 中文注释与提交信息；**不得推送**；提交用 `git -c core.hooksPath=/dev/null commit`
- 全量失败集去重必须 **≤ 41**（当前 41，用例 529）
- 五道门禁 exit=0：`check-migrations` / `check-docs` / `check-phpunit-config` / `check-env-example` / `lang:check`
- 另需 `php think env:check` exit=0
- **worker 不得并行跑 phpunit**

## Review Focus

- **去掉 `paths:` 后 check 必须每个 PR 都跑**：这是 R40 的全部意义。若只是把 `paths` 从 `pull_request` 挪到 `push`，required check 仍会卡死。
- **`check-migrations` 工作流必须真能跑通**：它要连数据库（检查 B 读 `migrations` 表）。CI 里没有 MySQL 时脚本会降级为告警——这会掩盖问题。必须处理这个差异，不能假装它在 CI 里等于本地。
- **R42 的缓存必须同时满足两件事**：文件未变 → **零 `parse_ini_file`**（只有 `stat`）；文件已变 → **重新检查**（修好 `.env` 后无需重启）。
- **`clearstatcache` 不能漏**：PHP 的 stat 缓存在长驻进程里会隐藏 mtime 变化，尤其 Swoole 场景。

## Task 1：R40 去掉 paths + R41 新增 migrations 工作流

**Files:**
- Modify: `.github/workflows/docs-check.yml`
- Modify: `.github/workflows/phpunit-config-check.yml`
- Modify: `.github/workflows/env-check.yml`
- Create: `.github/workflows/migrations-check.yml`

**已核实事实**
1. 三个工作流的 `on.pull_request` 与 `on.push` **都**声明了 `paths:`（见各文件）。
2. `AGENTS.md` 的「合并前必须通过的配置类门禁」小节已写明：带 `paths:` 的工作流设为 required 会让未命中路径的 PR 永久卡在 `Expected`；推荐做法是去掉 `paths:`。
3. `scripts/check-migrations.php` **没有任何工作流运行它**（`grep -l check-migrations .github/workflows/*.yml` 无匹配）。
4. `check-migrations.php` 的检查 B/E **需要连数据库**（读 `migrations` 表、读 `information_schema`）；
   连不上时会降级为告警并跳过（脚本里 `loadAppliedVersions()` 返回 null 的分支）。
   其中检查 E 的告警在 `--strict` 下会 **exit=1**，所以 CI 无 DB 时该工作流会红。
5. CI 环境参考：`.github/workflows/backend-php-cs-fixer.yml` 已存在，先读它看 CI 是否已有 MySQL/Redis service。

**要做**
### 1.1 去掉 `paths:`（R40）
- 三个工作流的 `pull_request` 与 `push` 都**删除整段 `paths:`**
- 保留 `push.branches`（`develop` / `main`）不动
- 在每个 `on:` 上方加注释说明：去掉 `paths:` 是为了让它能作为 **required status check**；
  代价是每次 PR 都会跑一遍（这三个门禁都是秒级纯校验，成本可接受）
- **同步更新 `AGENTS.md`** 的对应小节：把「推荐：去掉 paths:（后续动作）」改为「已完成」，
  并把「⚠️ 会卡住 PR」的警告改成「已通过去掉 paths 解决」，保留历史说明以便理解为什么当初会有这条

### 1.2 新增 `.github/workflows/migrations-check.yml`（R41）
- 照 `docs-check.yml` 结构
- **必须解决数据库依赖**，二选一并在注释里说明理由：
  - **方案 A（推荐）**：加 `services: mysql`（GitHub Actions service container），
    把 `DB_HOST/DB_NAME/DB_USER/DB_PASS` 通过 `env:` 传给脚本，让检查 B/E 真正生效。
    需要先确认 `scripts/check-migrations.php` 用什么方式连库（它 `require vendor/autoload.php` 后 `new think\App()` → `.env`/环境变量）。
    **CI 里没有 `.env`**，所以要么由 workflow 写一份临时 `.env`，要么确认 `env()` 能直接读到 `env:` 注入的变量
    （读 `think\Env::get` 的实现判断：`$_ENV` 优先于 `.env` 吗？—— 注意本项目是**先读 `.env` 填充的 data**，
    没有 `.env` 时才回落 `$_ENV`，所以 CI 无 `.env` 时 `env:` 注入是有效的）。
  - **方案 B（降级）**：无 DB，只跑不依赖库的检查 A/C/D，并**明确接受**检查 B/E 会跳过。
    若选这条，必须在 worklow 里加 `|| true` 之类**不行**——那会让门禁永远绿。正确做法是给脚本加
    `--no-db` 之类的显式开关，让 CI 与本地语义**显式不同**而不是靠告警兜底。
- 无论哪个方案，**先读 `scripts/check-migrations.php` 确认它的 DB 依赖降级行为**，
  再决定方案，并在报告里给出判断依据

## Task 2：R42 环境守卫的缓存签名

**Files:**
- Modify: `app/AppService.php`
- Modify: `tests/Unit/Command/EnvCheckCommandTest.php`（如有必要）或新建 `tests/Unit/AppServiceEnvGuardTest.php`

**已核实事实**
1. 现状：`protected static ?array $envFileReport = null;` + `guardEnvFile()` 里
   「同一进程只检查一次（结论不会变）」→ **一次 `parse_ini_file` 后永久缓存**。
2. 这带来一个真实运维死锁：**修好 `.env` 后，长驻进程（Swoole）仍会继续抛错，直到重启**。
   而注释「结论不会变」恰恰是错的——文件可以被修。
3. PHP 的 stat 缓存会让 `filemtime()` 在长驻进程里看不到新值，**必须先 `clearstatcache(true, $path)`**。
4. 守卫已在 `env:check` 诊断时跳过（argv 例外），不要破坏这条。

**要做**
- 把缓存改成**签名感知**：
  ```php
  protected static ?array $envFileReport = null;   // 保留：上次的检查结论
  protected static ?string $envFileSignature = null; // 新增：path|mtime|size
  ```
- `guardEnvFile()` 里：
  1. `clearstatcache(true, $path)`
  2. 取 `filemtime` / `filesize`（失败时用 `-1` 之类的哨兵值）
  3. 拼签名；**签名未变 → 直接复用 `$envFileReport`，不做任何 `parse_ini_file`**
  4. 签名变了 → 重新 `inspectEnvFile()` 并更新缓存
- 注释要说清两件事：为什么需要签名（自愈）、为什么需要 `clearstatcache`（stat 缓存）
- 不要改变 `env:check` 例外、不要改变 CLI 退出码修正

**验证（必须给原始输出）**
1. **零解析证明**：在同一进程内连续调用两次守卫逻辑，第二次不应触发 `parse_ini_file`。
   建议用一个可观测的方式证明（例如临时在 `inspectEnvFile` 里加计数器并用反射读取，
   或写一个直接调用 `guardEnvFile` 的测试并在 `inspectEnvFile` 上打桩）。
   **不能用「耗时变短」当唯一证据**——macOS bind mount 抖动大。
2. **自愈证明**：同一进程内
   - 先让 `.env` 是坏的 → 守卫抛异常
   - 再把它改好（**改 mtime**，注意可能同秒，必要时 `touch` 到不同时间）
   - 再调一次守卫 → **不再抛异常**
   （这条是 R42 的核心价值，必须给出可复现的证据；测试里用临时文件而非真实 `.env`）
3. 全量 `./vendor/bin/phpunit`：失败集去重 **≤ 41**，与基线 diff
4. 五道门禁 + `php think env:check` 全 exit=0
5. `php -l` 改动文件
