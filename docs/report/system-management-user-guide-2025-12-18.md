## 概述

系统管理模块是 AlkaidSYS 的核心管理功能，提供多租户环境下的组织、角色和权限管理能力。本模块采用 RBAC（基于角色的访问控制）模型，支持灵活的权限分配和精细化的访问控制。

### 模块架构

```
系统管理
├── 租户管理          # 多租户组织管理
├── 用户管理          # 用户账号管理
├── 角色管理          # 角色定义与权限分配
├── 权限管理          # 权限定义与维护
└── 权限监控          # 权限系统性能监控
```

### 前置条件

- 用户需要登录系统
- 用户需要具备相应模块的访问权限
- 管理员角色通常拥有所有系统管理权限

## 租户管理

### 功能概述

租户管理用于管理系统中的多租户组织。每个租户是一个独立的业务单元，拥有独立的用户、角色和数据隔离。

### 功能列表

| 功能 | 描述 | 所需权限 |
|------|------|----------|
| 查看租户列表 | 分页显示所有租户，支持搜索筛选 | `tenant.read` |
| 创建租户 | 新建租户组织 | `tenant.write` |
| 编辑租户 | 修改租户信息 | `tenant.write` |
| 删除租户 | 删除租户（需谨慎操作） | `tenant.delete` |
| 切换状态 | 启用/停用/暂停租户 | `tenant.write` |

### 租户属性说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 租户名称 (name) | 字符串 | 是 | 租户的显示名称 |
| 租户标识 (slug) | 字符串 | 是 | 唯一标识符，只能包含小写字母、数字、下划线和连字符 |
| 绑定域名 (domain) | 字符串 | 否 | 租户专属域名 |
| 状态 (status) | 枚举 | 是 | `active`（启用）、`inactive`（停用）、`suspended`（暂停） |
| 最大站点数 (max_sites) | 整数 | 否 | 租户可创建的最大站点数量，默认 1 |
| 最大用户数 (max_users) | 整数 | 否 | 租户可添加的最大用户数量，默认 10 |
| 到期时间 (expires_at) | 日期时间 | 否 | 租户服务到期时间 |

### 状态说明

- **启用 (active)**: 租户正常运营，所有功能可用
- **停用 (inactive)**: 租户暂时关闭，用户无法登录和访问
- **暂停 (suspended)**: 租户被管理员暂停，通常用于违规处理

### 操作指南

#### 创建租户

1. 进入「系统管理 → 租户管理」页面
2. 点击「新建租户」按钮
3. 填写租户信息：
   - 输入租户名称（如：北京分公司）
   - 输入租户标识（如：beijing-branch）
   - 可选填写绑定域名
   - 设置最大站点数和用户数
   - 设置到期时间（如适用）
4. 点击「确定」保存

#### 切换租户状态

1. 在租户列表中找到目标租户
2. 点击状态列的开关按钮
3. 在弹出的确认对话框中选择新状态
4. 确认切换

#### 删除租户

> ⚠️ **警告**: 删除租户将永久移除该租户的所有数据，此操作不可撤销。

1. 在租户列表中找到目标租户
2. 点击「操作」列的「删除」按钮
3. 确认删除操作

## 用户管理

### 功能概述

用户管理用于管理系统中的用户账号。每个用户属于一个租户，可以被分配多个角色，从而获得相应的权限。

### 功能列表

| 功能 | 描述 | 所需权限 |
|------|------|----------|
| 查看用户列表 | 分页显示当前租户的所有用户，支持搜索筛选 | `user.read` |
| 创建用户 | 新建用户账号 | `user.write` |
| 编辑用户 | 修改用户信息 | `user.write` |
| 删除用户 | 删除用户账号 | `user.delete` |
| 切换状态 | 启用/禁用/锁定用户 | `user.write` |
| 分配角色 | 为用户分配或移除角色 | `user.write` |
| 重置密码 | 重置用户登录密码 | `user.write` |

### 用户属性说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 用户名 (username) | 字符串 | 是 | 唯一标识，只能包含字母、数字、下划线，长度 3-50 字符 |
| 邮箱 (email) | 字符串 | 是 | 唯一邮箱地址，用于登录和通知 |
| 姓名 (name) | 字符串 | 否 | 用户真实姓名 |
| 手机号 (phone) | 字符串 | 否 | 手机号码 |
| 头像 (avatar) | 字符串 | 否 | 头像图片 URL |
| 状态 (status) | 枚举 | 是 | `active`（启用）、`inactive`（禁用）、`locked`（锁定） |
| 角色 (roles) | 数组 | 否 | 分配给用户的角色 ID 列表 |

### 状态说明

- **启用 (active)**: 用户正常状态，可以登录和使用系统
- **禁用 (inactive)**: 用户被停用，无法登录系统
- **锁定 (locked)**: 用户被锁定（通常因多次登录失败），需要管理员解锁

### 操作指南

#### 创建用户

1. 进入「系统管理 → 用户管理」页面
2. 点击「新建用户」按钮
3. 填写用户信息：
   - 输入用户名（如：zhangsan）
   - 输入邮箱地址（如：zhangsan@example.com）
   - 输入初始密码（至少 8 位，包含字母和数字）
   - 可选填写姓名和手机号
   - 选择要分配的角色
4. 点击「确定」保存

> 💡 **提示**: 建议在创建用户后通知用户修改初始密码。

#### 编辑用户

1. 在用户列表中找到目标用户
2. 点击「操作」列的「编辑」按钮
3. 修改用户信息（用户名和邮箱不可修改）
4. 点击「确定」保存

#### 分配角色

1. 在用户列表中找到目标用户
2. 点击「操作」列的「分配角色」按钮（或在编辑页面中）
3. 在角色列表中勾选要分配的角色
4. 点击「确定」保存
5. 角色变更会立即生效

> ⚠️ **注意**: 移除用户的角色会导致该用户失去相应的权限，请谨慎操作。

#### 切换用户状态

1. 在用户列表中找到目标用户
2. 点击状态列的开关按钮
3. 在弹出的确认对话框中选择新状态
4. 确认切换

#### 重置密码

1. 在用户列表中找到目标用户
2. 点击「操作」列的「重置密码」按钮
3. 系统会生成一个随机密码或发送重置链接到用户邮箱
4. 确认操作

> ⚠️ **安全提示**: 重置密码后，请通过安全渠道将新密码告知用户，并建议用户尽快修改密码。

#### 删除用户

> ⚠️ **警告**: 删除用户将移除该用户的所有数据，此操作不可撤销。

1. 在用户列表中找到目标用户
2. 点击「操作」列的「删除」按钮
3. 确认删除操作

> ⚠️ **限制**: 不能删除当前登录的用户（自己）。

## 角色管理

### 功能概述

角色管理用于定义和管理用户角色。角色是权限的集合，通过将权限分配给角色，再将角色分配给用户，实现灵活的权限控制。

### 功能列表

| 功能 | 描述 | 所需权限 |
|------|------|----------|
| 查看角色列表 | 分页显示当前租户的所有角色 | `role.read` |
| 创建角色 | 新建自定义角色 | `role.write` |
| 编辑角色 | 修改角色信息和权限 | `role.write` |
| 删除角色 | 删除自定义角色 | `role.delete` |
| 授权 | 为角色分配权限 | `role.write` |

### 角色属性说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 角色名称 (name) | 字符串 | 是 | 角色的显示名称 |
| 角色标识 (slug) | 字符串 | 是 | 唯一标识符，只能包含小写字母、数字、下划线和连字符 |
| 描述 (description) | 字符串 | 否 | 角色的功能描述 |
| 权限 (permissions) | 数组 | 否 | 分配给角色的权限 ID 列表 |

### 角色类型

- **系统角色**: 系统预置的角色，不可编辑和删除
  - `Administrator` - 超级管理员，拥有所有权限
  - `User` - 普通用户，基础权限
- **自定义角色**: 用户创建的角色，可自由编辑和删除

### 操作指南

#### 创建角色

1. 进入「系统管理 → 角色管理」页面
2. 点击「新建角色」按钮
3. 填写角色信息：
   - 输入角色名称（如：内容编辑）
   - 输入角色标识（如：content-editor）
   - 可选填写角色描述
4. 在权限面板中选择要分配的权限
   - 权限按资源类型分组展示
   - 可以点击组标题的「全选」快速选中整组权限
5. 点击「确定」保存

#### 编辑角色

1. 在角色列表中找到目标角色
2. 点击「操作」列的「编辑」按钮
3. 修改角色信息和权限设置
4. 点击「确定」保存

> ⚠️ **注意**: 系统角色无法编辑，编辑按钮会被禁用并显示提示。

#### 删除角色

1. 在角色列表中找到目标角色
2. 点击「操作」列的「删除」按钮
3. 确认删除操作

> ⚠️ **限制**:
> - 系统角色无法删除
> - 已分配给用户的角色无法删除，需先解除用户关联

## 权限管理

### 功能概述

权限管理用于定义和维护系统中的权限项。权限采用 `资源.操作` 的命名格式，支持细粒度的访问控制。

### 功能列表

| 功能 | 描述 | 所需权限 |
|------|------|----------|
| 查看权限列表 | 分页显示所有权限，支持搜索筛选 | `permission.read` |
| 创建权限 | 新建权限项 | `permission.write` |
| 编辑权限 | 修改权限信息 | `permission.write` |
| 删除权限 | 删除未使用的权限 | `permission.delete` |

### 权限属性说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 权限名称 (name) | 字符串 | 是 | 权限的显示名称 |
| 权限标识 (slug) | 字符串 | 是 | 唯一标识符，格式：`resource.action` |
| 资源类型 (resource) | 字符串 | 否 | 资源分类（如：user、role、tenant） |
| 操作类型 (action) | 字符串 | 否 | 操作类型（如：read、write、delete） |
| 描述 (description) | 字符串 | 否 | 权限的功能描述 |

### 权限标识命名规范

权限标识采用 `resource.action` 格式：

- **resource**: 资源类型，使用小写字母
- **action**: 操作类型，常用值：
  - `read` - 查看/读取
  - `write` - 创建/编辑
  - `delete` - 删除
  - `manage` - 管理（包含所有操作）

**示例**:
- `user.read` - 查看用户
- `user.write` - 创建/编辑用户
- `tenant.delete` - 删除租户
- `casbin.manage` - 权限引擎管理

### 内置权限列表

| 权限标识 | 权限名称 | 资源类型 | 操作类型 |
|----------|----------|----------|----------|
| `tenant.read` | 查看租户 | tenant | read |
| `tenant.write` | 管理租户 | tenant | write |
| `tenant.delete` | 删除租户 | tenant | delete |
| `role.read` | 查看角色 | role | read |
| `role.write` | 管理角色 | role | write |
| `role.delete` | 删除角色 | role | delete |
| `permission.read` | 查看权限 | permission | read |
| `permission.write` | 管理权限 | permission | write |
| `permission.delete` | 删除权限 | permission | delete |
| `user.read` | 查看用户 | user | read |
| `user.write` | 管理用户 | user | write |
| `user.delete` | 删除用户 | user | delete |
| `casbin.manage` | 权限引擎管理 | casbin | manage |

### 操作指南

#### 创建权限

1. 进入「系统管理 → 权限管理」页面
2. 点击「新建权限」按钮
3. 填写权限信息：
   - 输入权限名称（如：查看报表）
   - 输入权限标识（如：`report.read`）
   - 系统会自动从标识中提取资源类型和操作类型
   - 可手动修改资源类型和操作类型
   - 可选填写权限描述
4. 点击「确定」保存

#### 删除权限

> ⚠️ **限制**: 已被角色使用的权限无法删除，需先从所有角色中移除该权限。

1. 在权限列表中找到目标权限
2. 点击「操作」列的「删除」按钮
3. 确认删除操作

## 权限监控

### 功能概述

权限监控提供权限系统的性能监控和诊断功能，帮助管理员了解系统运行状态、优化性能、排查问题。

### 功能列表

| 功能 | 描述 |
|------|------|
| 性能概览 | 显示 P95 延迟、缓存命中率、总查询数等关键指标 |
| 缓存统计 | 显示 L1（内存）和 L2（Redis）缓存的详细统计 |
| 缓存管理 | 清除所有缓存或刷新统计数据 |
| 用户权限查询 | 查询指定用户的权限列表 |
| 权限检查 | 检查指定用户是否拥有特定权限 |

### 性能指标说明

#### 核心指标

| 指标 | 说明 | 目标值 |
|------|------|--------|
| P95 延迟 | 95% 的请求响应时间 | < 100ms |
| 缓存命中率 | 缓存查询命中的百分比 | ≥ 90% |
| 总查询数 | 权限检查的总请求次数 | - |
| 平均延迟 | 所有请求的平均响应时间 | - |

#### 缓存层级

系统采用两级缓存架构：

- **L1 缓存（内存）**: 本地内存缓存，速度最快，TTL 较短
- **L2 缓存（Redis）**: 分布式缓存，支持集群环境，TTL 较长

### 操作指南

#### 查看性能概览

1. 进入「系统管理 → 权限监控」页面
2. 顶部卡片显示四个核心指标：
   - P95 延迟（绿色 < 100ms，黄色 ≥ 100ms）
   - 缓存命中率（绿色 ≥ 90%，黄色 < 90%）
   - 总查询数
   - 平均延迟

#### 清除缓存

当权限配置发生变更但未生效时，可手动清除缓存：

1. 点击「清除所有缓存」按钮
2. 等待操作完成
3. 统计数据会自动刷新

> ⚠️ **注意**: 清除缓存后，首次权限检查会较慢，因为需要重新加载数据。

#### 查询用户权限

1. 在「用户权限查询」区域输入用户 ID
2. 点击「查询权限」按钮
3. 系统显示该用户拥有的所有权限标识

#### 检查特定权限

1. 输入用户 ID
2. 输入权限标识（如：`user.read`）
3. 点击「检查权限」按钮
4. 系统显示该用户是否拥有该权限

## 用户故事

### US-001: 作为管理员，我想创建一个新租户

**场景描述**:
公司新成立了一个分公司，需要在系统中创建独立的租户进行管理。

**操作步骤**:
1. 管理员登录系统，进入「系统管理 → 租户管理」
2. 点击「新建租户」按钮
3. 填写租户信息：
   - 租户名称：上海分公司
   - 租户标识：shanghai-branch
   - 最大用户数：50
   - 到期时间：2026-12-31
4. 点击「确定」保存
5. 新租户创建成功，默认状态为「启用」

**预期结果**:
- 租户列表中显示新创建的租户
- 新租户可以开始添加用户和配置

---

### US-002: 作为管理员，我想创建一个具有特定权限的角色

**场景描述**:
公司需要一个「内容审核员」角色，只能查看和管理内容，不能修改系统设置。

**操作步骤**:
1. 管理员进入「系统管理 → 角色管理」
2. 点击「新建角色」按钮
3. 填写角色信息：
   - 角色名称：内容审核员
   - 角色标识：content-reviewer
   - 描述：负责审核用户发布的内容
4. 在权限面板中选择：
   - 「集合管理」组的 `collections.read`
   - 「表单管理」组的 `forms.read`
5. 点击「确定」保存

**预期结果**:
- 角色列表中显示新创建的角色
- 显示该角色拥有 2 项权限
- 分配该角色的用户只能查看内容，无法进行系统管理操作

---

### US-003: 作为管理员，我想添加一个新的权限项

**场景描述**:
开发团队新增了报表功能，需要添加对应的权限进行访问控制。

**操作步骤**:
1. 管理员进入「系统管理 → 权限管理」
2. 点击「新建权限」按钮
3. 填写权限信息：
   - 权限名称：查看报表
   - 权限标识：`report.read`
   - 资源类型：report（自动提取）
   - 操作类型：read（自动提取）
   - 描述：查看系统统计报表
4. 点击「确定」保存
5. 类似地创建 `report.export`（导出报表）权限

**预期结果**:
- 权限列表中显示新创建的权限
- 在角色管理的权限面板中，「报表」分组下显示新权限
- 可以将新权限分配给相应角色

---

### US-004: 作为管理员，我想暂停一个违规租户

**场景描述**:
某租户被举报存在违规行为，需要暂停其服务进行调查。

**操作步骤**:

## 常见问题

### Q1: 为什么无法编辑系统角色？

**A**: 系统角色（如 Administrator、User）是系统预置的核心角色，为确保系统安全和稳定性，这些角色不允许修改和删除。如需自定义权限配置，请创建新的自定义角色。

### Q2: 为什么无法删除某个角色？

**A**: 可能原因：
1. 该角色是系统角色，系统角色不可删除
2. 该角色已分配给用户，需先解除用户与角色的关联

### Q3: 为什么无法删除某个权限？

**A**: 该权限正在被某些角色使用。需要先进入角色管理，从所有使用该权限的角色中移除该权限，然后才能删除。

### Q4: 修改权限后为什么没有立即生效？

**A**: 权限系统使用缓存来提高性能。权限变更后，可能需要等待缓存过期或手动清除缓存：
1. 进入「权限监控」页面
2. 点击「清除所有缓存」按钮
3. 等待缓存重建

### Q5: 如何设计合理的权限结构？

**A**: 建议遵循以下原则：
1. **最小权限原则**: 只授予用户完成工作所需的最小权限集
2. **角色分层**: 创建层级化的角色体系，如：观察者 → 操作员 → 管理员
3. **权限命名规范**: 统一使用 `resource.action` 格式
4. **定期审计**: 定期检查用户权限，移除不必要的权限

### Q6: 缓存命中率持续较低怎么办？

**A**: 可能原因及解决方案：
1. **Redis 连接问题**: 检查 Redis 服务是否正常运行
2. **TTL 设置过短**: 检查缓存 TTL 配置，适当增加缓存时间
3. **用户分布分散**: 如果用户访问模式很分散，可以增加缓存容量

### Q7: 为什么无法删除某个用户？

**A**: 可能原因：
1. 不能删除当前登录的用户（自己）
2. 该用户可能是某些资源的创建者或所有者
3. 可能存在业务数据关联（如审批记录）

### Q8: 用户修改角色后权限没有生效怎么办？

**A**: 用户角色变更后，权限系统会自动刷新缓存。如果仍未生效：
1. 让用户重新登录系统
2. 进入「权限监控」页面，清除该用户的缓存
3. 检查角色是否正确分配了所需权限

### Q9: 如何批量创建用户？

**A**: 当前系统支持单个创建用户。如需批量创建：
1. 使用 API 接口批量调用创建用户端点
2. 或联系技术支持提供导入功能

### Q10: 用户密码有什么要求？

**A**: 密码安全策略：
1. 最少 8 位字符
2. 必须包含字母和数字
3. 建议包含大小写字母和特殊字符
4. 不能与用户名相同
